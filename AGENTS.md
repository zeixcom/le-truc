# Agent Context — Le Truc

> Non-obvious facts and easy-to-get-wrong behaviors only. Structure: `ARCHITECTURE.md`. API details: JSDoc in `src/`. Authoring or reviewing a compiled component? Read `server/compiler/HOST_PROFILE.md` first — `.tsx` is the default authored surface, `.tsrx` stays supported where statement-context control flow reads better (ADR 0032), and this project's host decisions (styles, `truc:pass`, element references) differ from Ripple's, the only other TSRX host profile.

## Factory Form

The factory form is the only way to define components. Effect helpers (`watch`, `on`, `pass`, `each`, `provideContexts`) self-register in an ambient collector when called and return `void` — the collector is the only registration path, so a factory returns nothing (ADR 0018; since v3.0 `FactoryResult` is gone).

```ts
defineComponent<MyProps>('my-element', ({ expose, first, on, watch }) => {
  const input = first('input') as HTMLInputElement
  expose({ value: input.value })
  on(input, 'input', () => ({ value: input.value }))
  watch('value', v => { input.value = v })
})
```

## Surprising Behaviors

- **One tag, one authored source per surface — variants are folder-local**: a corpus folder may carry a **variant set** — the `.ts` twin, the `.tsrx` and the `.tsx` spelling, all declaring one canonical tag (ADR 0039). The build compiles every member, asserts their CSS byte-identical, and serves the selected surface's artifacts under the canonical names (`.tsx` by default; `variantSurface`/`variantOverrides` in `le-truc.config.json`). A tag two same-surface files declare — or that two folders declare — still fails the build naming both (LTC048). Every member of a variant set declares its own `declare global` `HTMLElementTagNameMap` entry (ADR 0039 s4): `check:corpus` sees only the served member, and a composing parent types through that member's entry. Identical entries merge; a Props type diverging between two members in one tsc program is a TS 2717 error. Migrate a tag to `.tsx` by **adding** the `.tsx` source alongside the `.tsrx` twin — it then becomes the served surface — not by replacing the twin.

- **The boundary is three-arm in both surfaces; the in-flight state is the `isPending` idiom**: `<truc:try pending={…} catch={e => …}>` in `.tsx`, `@try`/`@pending`/`@catch` in `.tsrx` (ADR 0041) — there is no `stale` arm anywhere (owner withdrawal, LT-211: a re-fetching task keeps its `ok` arm, whose content is never re-rendered). Reactive idiom: `class={() => (isPending(data) ? 'pending' : null)}` — the ARROW is required (a bare expression is a render-time `server` attribute that never updates). Arms are typed `JSX.Element`/`err: Error` (LT-208). The `css` tag remains `.tsx` vocabulary and the `{count}` shorthand `.tsrx`-only.

- **A condition that reads a signal or `host` switches template-cloned arms, not toggled ones** (ADR 0037, LT-274/LT-276): `@if`/`@switch`, a `.tsx` ternary/`&&`/switch IIFE, and the async boundary render only the winning arm live (its root carries `data-key` = `then`/`else`/`case:<value>`/`default`, or `ok`/`nil`/`err`), followed by one inert `<template data-arms="N" data-key>` per arm. The client's `reconcile(container, templates, keyThunk, bindArm)` adopts the winner by key and clones on a flip; re-entry clones afresh, so uncommitted input in an arm is lost. Each arm needs exactly one root element; arm effects mount inside `bindArm` and die with the arm. The conditional must sit directly in an element of its Mount Scope — the host, an arm or a list item; arm sets and lists nest by recursion (ADR 0046, LT-424) — not in a server-rendered branch, a server-data loop body or composed content; a reactive `@case` value must be a literal (LTC062), and a reactive list's container cannot hold one (LTC063). The mirror rule holds too (LT-468): a client construct on an element in a server-rendered branch of a list item — the branch roots and a nested list's branch-held container included — is refused (LTC005), since the fold is fixed per render and per clone and the construct's required query would throw in every item mount; make the condition reactive, which plans an arm set with existence-guarded binding. The compose case is refused the same way (LT-470): a `truc:pass` onto a composed child in a server-rendered branch — of a list item, where the entries minted a required local that threw in every item mount when the branch folded off, or of the host, where they were silently unplanned — fails the compile (LTC005); a pass-less composed child stays legal and renders into the template. A test no server phase evaluates renders no live arm. `first()` into an arm — or into a reactive-list item (ADR 0046: the item is a Mount Scope whose content lowers through the same arm emission, its extracted template stamped `data-list="N"` outside the container) — is refused: the element is recreated on every flip or reconcile.

- **Typed factory context on `.tsx`: annotate the second parameter** (LT-209): `, { host, first, expose }: FactoryContext<Props>` (form-associated: `FormFactoryContext<Props>`). It shadows the wide ambients at function scope, makes `watch`/`on`/`pass` prop-key-precise, and turns a mistyped `expose()` key into a free tsc error (P-drift). Wrong surface annotation → LTC050; unknown destructured name → LTC049. `i18n` stays in the ARGS destructure — the generated client has no `i18n` record. No silent fallbacks: omit the param and you get the ambients; an unannotated param is an implicit-`any` error under strict.

- **Messages are ICU MF1 patterns, typed per key**: declare `export const i18n = { … } as const` and annotate the parameter `i18n: I18n<typeof i18n>`. A pattern without `{` types as `string`; one with `{` is a call, `t.tasks({ count })`. Plurals, `select` and number/date formatting live in the pattern. Variance beyond words (different markup per case) is a ternary or `@if`/`@switch`. Omit `as const` and every key widens to the `string | function` union — first attribute read fails tsc. Authored-side typing classifies by brace only: an ICU-escaped literal brace (`'{'`) in an argument-less pattern types as a call; LTC055 and the generated modules are exact.

- **`t.<key>` reads compile in client positions and ship via the root `i18n` attribute**: a thunk, handler, `expose()` entry, client-only setup statement or list-item handler may read a declared key statically (`t.done`, `t['a.b']`). The server serializes those keys' parsed patterns per render locale, omitting keys equal to the source, so a source-locale render usually writes no attribute; the client re-evaluates on argument change. Computed `t[key]`, bare `t`, `i18n.t.<key>` and `lang` stay server-only (LTC005; client spelling is `host.lang`). Root `lang` is the client's only locale source — serialized messages carry none; compiler writes `lang` on a component whose client messages format (number, date, plural) but that binds no `lang`. An instance created outside a compiled parent's render shows source strings.

- **`observedAttributes` is opt-in — parsers run once**: `defineComponent` never registers `observedAttributes`/`attributeChangedCallback` on its own. Parsers passed to `expose()` read the attribute once at connect, for server-rendered configuration. Pass the `observedAttributes()` extension to re-run a Parser-backed prop's parser on later attribute mutations; otherwise react via events or `watch()`.

- **Branding, not structure, distinguishes parsers and method producers**: `isParser()` checks `PARSER_BRAND`, `isMethodProducer()` checks `METHOD_BRAND`. Always use `asParser()` / `defineMethod()`. An unbranded `() => void` is wrapped in `deriveCell()` as a `MemoCallback`, not installed as a method producer — silently wrong, no error.

- **A hand-authored `EffectDescriptor` silently never cleans up**: only the effect helpers self-register cleanup via their internal `createEffect()`/`createScope()`. A raw descriptor (`() => { setup(); return cleanup }`) returned bare has its cleanup dropped — it never runs on disconnect. Wrap it: `watch(() => true, descriptor)`.

- **`pass()` is Le Truc–only and replaces signals, not values**: it calls `slot.replace(signal)` on the child's internal Slot map, so it only works for Le Truc components with Slot-backed properties. For any other element use `watch(source, bindProperty(el, key))`, which goes through the public JS setter. `pass()` captures the original signal and restores it on parent disconnect, so the child regains independent state after detachment. The property-key (`'value'`) and bare-signal short forms were removed in v3.0 (ADR 0012) — a thunk (`() => host.prop`, read-only) or a `{ get, set }` descriptor (mediated writes) is the only accepted input; a retired form, including a bare read-only signal, fails the eager validation and swaps nothing.

- **`all()`'s MutationObserver is lazy**: it activates only when the returned `Cell` is read inside a reactive effect, and watches only the attribute changes implied by the CSS selector. The `equals` check is fully respected — an `innerHTML` mutation that doesn't change the match set re-runs nothing.

- **`setAttribute` validates**: blocks `on*` handler attributes and checks URL attributes against a safe-protocol allowlist (`http:`, `https:`, `ftp:`, `mailto:`, `tel:`). Violations throw, never silently pass.

- **Dependency resolution races the child's own upgrade**: if a queried custom element isn't defined within `DEPENDENCY_TIMEOUT`, a `DependencyTimeoutError` is logged and the parent's effects activate anyway against a possibly-undefined child — intentional progressive enhancement. Writing a not-yet-upgraded child's `expose()`d property is safe: at upgrade, `#initSignals` captures the pre-connect write as the initial signal value and installs the accessor anyway (ADR 0031) — the write outranks static and Parser initializers, a declared `Signal`/thunk/`SlotDescriptor` initializer wins over the write, and inherited prototype-managed members (`localName`, `lang`, …) keep being skipped.

- **`on()` handler return value updates the host**: returning `{ prop: value }` applies those updates in a `batch()`. Returning nothing is a no-op.

- **Context follows the Web Components CG protocol**, with retries: `requestContext(context, fallback)` returns a `Signal<T>` (Slot-backed, the same primitive `pass()` uses) usable directly in `expose()`. If no ancestor answers the initial dispatch, it re-dispatches on a microtask and again after a short timeout, covering providers upgraded later or awaiting `customElements.whenDefined()`. The Slot serves `fallback` until a provider answers; after the last retry the fallback is permanent for that connection. Resolution happens once per component lifetime, at first connect — reconnect re-activates cached descriptors without re-running the factory, so no re-dispatch.

- **Providers are stable single sources of truth**: update the value they provide; don't add/remove providers at runtime. A connected consumer keeps the provider's last value for the life of the connection — removing the provider does not revert it to `fallback`. This prevents flicker when a consumer briefly disconnects during a DOM move (e.g. drag-and-drop). Give consumers a `fallback` that makes sense for a genuinely absent provider.

- **A nil value routes to `nil`, and a plain handler ignores it**: `null`/`undefined` from a reactive (or an unset Task) calls the `nil` handler, not `ok`. A plain-function handler — `bindText`, `bindProperty`, your own — gets no call, so the DOM keeps its last value. Only the match-handler bindings act on `nil`: `bindAttribute` removes the attribute, `bindStyle` calls `removeProperty` (restoring the cascade value), `bindAria` assigns `null`, `dangerouslyBindInnerHTML` resets the content.

- **`expose()` accepts a `{ get, set? }` descriptor**, installed directly as the property's backing Slot — the same mediated form `pass()` accepts. Prefer it over a pair of `watch` calls kept in sync by hand, which need an equality guard against re-entrant circularity. Omit `set` for read-only (writes throw `ReadonlySignalError`). See `examples/form/tokenbox/form-tokenbox.tsrx`. For an event-driven read-only prop, expose `state.get` (not the full `State`) and update it in an `on()` handler; to watch it inside the factory pass the signal directly.

- **`expose()` on a built-in IDL property name is silently skipped**: `'lang' in this` (also `dir`, `title`, `hidden`, every global-attribute reflection) is always true, so `#initSignals`'s `prop in this` guard skips the initializer before any accessor is installed — no error, no reactivity, and reads hit the native accessor (the live attribute). The attribute is the only channel for these names: seed it, don't expose it (the `c-plural` compiler fixture materializes its walked locale onto the `lang` attribute at connect; LT-191). A parser-applied seed doesn't help — the guard runs first.

- **Form reset is deferred and restores from the baseline, not the initializer**: form reset runs in tree order, so a form-associated host's `formResetCallback` fires *before* its inner native control resets itself — the restoring write (`this[prop] = this[defaultProp]`) is therefore deferred to a microtask, and a test must `await Promise.resolve()` before asserting. `defaultValue`/`defaultChecked` are managed prototype members: the getter re-parses the live attribute through the retained `Parser`, the setter writes or removes the attribute, and setting them moves only the *next* reset's baseline. Never put `value`/`checked` into `observedAttributes()` on a form-associated component — that re-parses the baseline attribute into the live prop. A native `<input>` also updates a clean control's live value on reset; that is unimplementable from JS (the dirty flag is write-only), so the deviation is deliberate.

- **Dev mode needs the *string* `"true"`**: build with `--define process.env.DEV_MODE='"true"'`; guards compare `=== 'true'` inline, so a bare boolean disables them. Production defines `"false"`, constant-folding dev branches out. `DEV_MODE` has no per-instance override; the per-instance `debug` property (ADR 0022) only toggles instrumentation.

- **Testing a DEV-gated branch is an env flip, not a module mock**: guards read `process.env.DEV_MODE` at call time, so set `process.env.DEV_MODE = 'true'` around the call and restore the previous value in a `finally` (see `withDevMode` in `src/tests/context.test.ts`). The var is process-global: while an awaited DEV window is open, guards in interleaved tests see it too — that only produces extra `console.warn` calls, so keep warn-counting assertions in the file that flips it.

- **`bindVisible` is the inverse of `hidden`**: `bindVisible(el)` sets `el.hidden = !value`.

- **`bindAttribute` returns `SingleMatchHandlers`, not a function** (`watch` accepts both), and dispatches on type: a boolean value calls `toggleAttribute`, so don't pass boolean for attributes needing a string value.

- **`stale` in `watch` only fires for async sources with a retained value**: precedence is `nil` > `err` > `stale` > `ok`; it requires both a retained value and `isPending(signal)` — a `Task`, or a list or store derived from an async computation (its internal Task carries the pending state), never `State` or `Memo`. `isPending` sees through a Slot, so a `pass()`ed async thunk fires the child's `watch('prop', { stale })` (cause-effect ≥ 1.6.1, LT-412). Without `{ value: seed }` the first read throws `UnsetSignalValueError` and routes to `nil`. Omitting `stale` falls back to `ok`, leaving the retained value in place during a re-fetch.
