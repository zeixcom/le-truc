## Compiler — LT-165 step 5 reclassification: four decisions the ADR table left open
**Date:** 2026-09-06 | **Skill:** le-truc-dev
Step 5 retired `TSRX004`/`TSRX013`-server-eval/`TSRX043`/`TSRX033`-reactive/`TSRX034`-non-severe from the channel (baseline now 0). Four things needed judgement beyond ADR 0029 s5's table:

1. **Rendered client-only consts became `TSRX046` (new error), not a free pass.** Removing the `TSRX013`/`TSRX043` errors exposed a residue the ADR table didn't consider: a client-only const whose VALUE is rendered into the markup (`<span>{initial}</span>` where `initial = input.value`, or `{lowerFilter}` over a `createMemo(() => host.x)`). Unrendered, the shape routes Simulated and works (client declares the const, tier-aware emit drops it). Rendered, the static splice has no server answer in ANY tier and no client binding corrects it — same structural class as `impureStaticChild`, so it stays an error, now precisely scoped to the actual unsoundness instead of refusing every ref-reading const. ADR 0029 s5's rationale ("on the Simulated tier the value is resolved") only holds for the unrendered case. LT-093 step 1 anticipated this rendered/not-rendered split for `TSRX004`; the same shape appeared here for `TSRX013`/`TSRX043`. The Tech Writer reviewed the `TSRX046` copy with the other retirements.
2. **`TSRX034`-severe scoping is component-tier, per the ADR's literal wording — with a known edge.** Implemented as a post-`classifyTier` filter in `index.ts` (severe `TSRX034` errors dropped unless tier is `static`; the error gate moved after tier computation). Edge: a Simulated-tier component (via some other realm-answerable signal) carrying a severe site whose OWN resolution is `none` — e.g. `disabled={() => busy.get() && Math.random() > 0.5}` in a form-associated component that also has a realm-answerable site — has the diagnostic silenced, though its own value is still omitted. Per-expression scoping (fire iff `resolutionOf` says `none`) would catch that case; the ADR says "scoped to the Static tier" twice, so the literal reading won. No corpus component hits the edge. If an Architect prefers per-expression scoping, the filter in `index.ts` is the single place to change.
3. **Retention over-match could break suppressed-tier modules; the pool now excludes harness-unevaluable statements.** `retainReferenced` matches declared names against generated text by identifier boundary — `<c-el>` tokenises as containing `el`, so a client-only const named like a word in the markup got retained, emitting `all('.foo')`/`input.value` into a render function that cannot run them (undeclared name; a crash if executed). `emit-server.ts` now filters statements whose free names hit `CLIENT_ONLY_PRIMITIVES`, ref names, or `host`/`internals` out of the retention pool (requestContext-declared signals exempt — their emitted `createCell(fallback)` form is harness-evaluable; card-mediaqueries caught that exemption the hard way). A GENUINE markup reference to such a name is an unsound shape → `TSRX046` at the compiler level; an INDIRECT one (const → const → ref) surfaces as source-mapped tsc on the generated module (LT-136 posture; LT-093/LT-135 territory).
4. **`Date` analysis, decided as the ADR 0030 resolution implies.** `new Date(y, m, d)` over server-known args stays impure: it reads no viewing-moment fact, but the local-time constructor interprets in the build machine's TIMEZONE, which is limb-(b) ambient state — the rendered day must not depend on where the build ran. `Date.UTC(y, m - 1, d)` is now admitted (pure — fixed function of its args, no clock, no zone), with nested impurity still caught (`Date.UTC(2026, 0, Date.now())` flags). This is what makes LT-095's prescribed blogmeta shape (`Date.UTC` + `timeZone: 'UTC'`) foldable when that migration lands. Pinned in `evaluability.test.ts` + `tier.test.ts`.

Two enabling fixes the reclassification required to avoid silent breakage, both pinned by tests: `emit-client.ts` declares unharvested signals verbatim in the client module (the realm replays that module — without the declaration a TSRX004-routed component's effects would ReferenceError at connect, contained and silent; a non-portable initializer, e.g. reading a server param, surfaces as tsc on the generated module), and the `clientOnlySignalCompute` const now registers as plain setup so it can reach the client module at all.

## Tooling — Mimosa PreToolUse hook false-positives on `server/tsrx/runtime.ts`
**Date:** 2026-08-29 | **Skill:** le-truc-dev
During LT-090, Mimosa twice rejected Edits to `runtime.ts` as "command injection" — a false positive on HTML-escaping string building (that module has no process execution; the flagged region was pre-existing `esc()`/`attr()` code). Workaround: place render-time helpers in their own module (`compose-attrs.ts`) and re-export through `runtime.ts`. Future edits to `runtime.ts` may hit the same heuristic — if a legitimate edit is blocked, check whether the flagged pattern is pre-existing escaping code before restructuring.
