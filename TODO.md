- [x] LT-142: Make `Intl` server-foldable when its locale resolves to a server-known value — split it from `Date`.
  **Skill:** le-truc-dev
  **Context:** **Owner decision, 2026-09-02.** `evaluability.ts:29` holds `IMPURE_AMBIENT_ROOTS = new Set(['Date', 'Intl'])`, so every `Intl.*` construction disqualifies the whole expression from the server fold (all-or-nothing, by design). Lumping the two together was the original conservatism, and it is wrong on the merits: `Date.now()`/`new Date()` are *not deterministic at all* — a fold would bake the build timestamp into shipped HTML — while `Intl.PluralRules`/`Intl.NumberFormat`/`Intl.DateTimeFormat` are **deterministic given a locale**. **Decision:** `Intl` is foldable when its locale argument resolves to a server-known value (a server arg, a literal, or a server-known const); it stays impure when the locale is unresolvable. `Date` is unchanged and stays impure. Where the folded value and the client's eventual value disagree (the page's `lang` differs from the arg), the client thunk re-runs at connect and corrects — this is **exactly the precedent ADR 0024 sub-design 15 already set** for `requestContext` fallbacks ("the server renders using the fallback, the client corrects away from it once the real value resolves"), and sub-design 3's documented flash tradeoff. **Do not widen `IMPURE_AMBIENT_METHODS`** — `Math.random()` has no locale to resolve and stays impure. **Fixture first:** write the failing probe before touching the set; the two corpus consumers (LT-143, LT-133) are reshaped separately and must not be the test. Acceptance: an `Intl.NumberFormat(<server arg>)` thunk folds; the same thunk with an unresolvable locale still does not; `Date.now()` still does not; the 8-warning baseline drops only by what LT-143/LT-133 then claim.
