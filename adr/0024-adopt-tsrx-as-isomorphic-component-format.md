# ADR 0024: Adopt TSRX as the Isomorphic Component Format

## Status

✅ Accepted (2026-08-22). Implemented in the inlined compiler (`server/tsrx/`), golden-tested in `server/tests/tsrx/`. The sanctioned subset covers server evaluation and client codegen, DOM-is-truth harvesting from a component's own rendered children, reactive `@for` over a `List` via `reconcile()`, type flow by emit-then-check, component composition, optional element references and optional `@if` branches, multi-arg/multi-site signal substitution, and async boundaries (`@try`/`@pending`/`@catch`). The 22-component corpus in `examples/` compiles end to end; `basic-button` is the harvest reference.

Amended 2026-08-30 (LT-117/121/122/123): sub-designs 3 and 11 were widened after the first attempt at a template-owning component with harvested props and optional children hit four diagnostics and was implemented as an opt-in `enhancer` mode that lifted all four. That mode is **rejected and removed** — see Alternatives. The re-diagnosis found the real gap in neither of the four: a render site could serve the server or the client, never both.

Amended again 2026-08-30 (LT-118): sub-design 3's server-evaluation rule was widened by two fold sources — a harvested prop folds from the arg that renders its site, and a `first()`-bound ref's presence folds from the `@if` condition that decided whether the server rendered its element. LT-118's own premise (union addressing over structurally differing `@if`/`@else` branch roots) was **wrong** and is recorded as such: the hand-written twin it restores toggled `hidden` over always-present elements. What the task actually needed was for the compiler to stop charging a penalty for following the data account.

Selector fidelity landed 2026-08-30 (LT-124): a class discriminator is synthesized as a token clause (`span.label`, the authored form) rather than exact-match `[class="label"]`, so page-authored markup carrying extra classes is addressed — the failure optional references (sub-design 11) had made silent. Open, non-blocking follow-up: in-editor (Volar) diagnostics (LT-014); async-boundary residue — reactive `html={() => …}`, optional addressing inside a plain `@try` body, `createMemo` as a recognized signal constructor (LT-025); a reactive host-level CSS custom-property lowering, gated on a proposed library-level `bindStyle()` map-form extension (LT-028, LT-029). Import-placement inference for plain imports (LT-034, sub-design 14) and context protocol support (LT-035, sub-design 15) both landed. The authored-import policy was re-amended 2026-08-27 (sub-design 16): FactoryContext vocabulary returns to the `globals.d.ts` ambient contract, real package exports require explicit authored imports — implemented and reviewed as LT-082 (2026-08-29); the same-day LT-079 explicit-import-over-context-names experiment is fully superseded, corpus and test suite green.

## Context

Every Le Truc component is authored as three hand-maintained files (`.ts` / `.html` / `.css`) whose mutual contract is checked only at runtime — `first()` failures are the symptom, drift is the disease. REQUIREMENTS.md [§1](../REQUIREMENTS.md#the-core-insight) requires server-rendered HTML with a thin reactive enhancement layer, [§5](../REQUIREMENTS.md#5-technical-constraints) prohibits client-side rendering and any SSR layer *in the library*, and [§7](../REQUIREMENTS.md#7-out-of-scope) anticipated a companion project for the server half. TSRX (Ripple ecosystem) is a TypeScript superset with a shared parser (`@tsrx/core`) and per-target codegen; every existing target renders and re-renders its own DOM — Le Truc would be the first server-oriented target. Two Phase 0 spikes validated the direction on `@tsrx/core` 0.1.60 before this ADR was written: every syntactic position needed is grammar-native, and hand-compiling isomorphic sources reproduces today's hand-written components statement for statement.

## Decision

Adopt an **isomorphic single-file `.tsrx` format** — server args, signals, `expose()`, markup, event handlers, and scoped styles in one source, the single source of truth for both the server render and the client enhancement — compiled by a **split compiler** built in-repo on pinned `@tsrx/core`. Sub-designs:

1. **One format, no coexistence.** The isomorphic format is the only authoring format. No authored-client fallback, no escape hatches; event delegation is a compiler optimization for bubbling events. The Option C spike remains a feasibility proof, never a shipping format.
2. **Split compiler, isolated dependency.** Server evaluation runs the `@{ }` setup once (signals as plain values) and renders HTML; client generation emits a `defineComponent()` factory that imports solely from `@zeix/le-truc` (CE v2 names via the 2.5.1 bridge). Authored sources import the real `@zeix/le-truc` exports their setup code references (sub-design 16); the FactoryContext vocabulary is ambient, and the effect machinery (`watch`/`on`/`pass`/`each`) is generated, never authored. `@tsrx/core` is pinned at 0.1.60 behind one emitter module; upgrades are reviewed changes. CSS is emitted verbatim, tag-scoped, no class hashing. The compiler is **inlined in this repo — no separate package ships before TSRX reaches 1.0**; with Le Truc v3.0 it ships as `@tsrx/le-truc`, while `@zeix/le-truc` remains the backend-agnostic client layer.
3. **DOM-is-truth seeding, end to end.** The server renders each reactive expression's initial value; the client harvests its initial state from that DOM (ADR [0003](0003-attributes-drive-state-at-connect-time-only.md) preserved; no serialized state payload). Lists seed from server args server-side and are adopted from the rendered HTML client-side. Harvest canonical site: first by document order, DEV_MODE warns on disagreement.Thunk attributes are server-evaluated when their dependency closure is server-known (args, seeded list state); otherwise omitted — `<template>` clones auto-augment on client insertion — with authored static markup controlling the no-JS initial state.

   **Server-known is wider than the arg scope (amended 2026-08-30, LT-085/LT-118).** A thunk that reads no arg may still have a server truth the compiler can reach, and three routes do: a Parser-exposed prop reads it from the root attribute that seeds it; a HARVESTED prop reads it from the server arg that renders its site (sub-design 3's one-site-three-roles rule, seen from the server end); and a `first()`-bound ref read as a bare identifier — a presence test — reads it from the `@if` condition that decided whether the server rendered the element at all. Each is a splice-and-evaluate over the authored expression, all-or-nothing: one unsubstitutable read omits the whole attribute, because a partially folded thunk bakes a plausible-looking wrong state into the HTML, which is worse than a correctly empty one. The rule earns its place at ADR level because of what it protects on the AUTHORING side: without it, an author who gates an optional affordance on a local ref — the hand-written idiom — is pushed into exposing a reactive public prop purely to give the compiler something server-known to read, letting a compiler limitation dictate a component's public contract.

   **One site, three roles (amended 2026-08-30, LT-122).** A prop a component harvests from its own children is rendered into that site from the component's SERVER ARG (`<span class="label">{label}</span>`), harvested back out of the same site at connect (`expose({ label: labelSpan?.textContent ?? … })`), and rebound there when the prop is written afterwards. The site is simultaneously the server's render target, the client's harvest source, and the client's binding target. This is what makes bullet 2 of the data account — a component never demands as a host attribute what its owned children already carry — expressible at all: before it, an expression naming a server arg (`{label}`) server-rendered but planned no client effect, while the `host.<prop>` spelling planned the effect but server-rendered empty, so a harvesting component could render its data or bind it but not both. The rule is a coincidence rule over existing machinery, not new syntax: an expression naming BOTH a server arg and an `expose()`d prop of that name plans the effect the `host.<prop>` spelling plans. Three exclusions, each for a different reason — declared signals (they own a render site and a harvest plan already), the root element's own attributes (the root IS the host, so a prop rendered there is the channel, not a copy), and PARSER-exposed props, whose seeding channel is the host attribute: rendering the same value into an owned site ships it twice and would fight a native control's dirty-value flag, so that shape warns instead of binding.
4. **Author-declared reactivity, no marker identifiers.** On a native element, a function-valued attribute is a reactive DOM binding (`watch()` plus the matching `bind*` helper); `on*`-prefixed are events (stripped server-side); a `{expr}` child whose expression is reactive is the grammar-native reactive child (the `&{ }` sigil this ADR originally specified was removed by LT-052 — reactivity is inferred from what the expression READS, not from a marker). No upstream grammar changes required. Interop with a custom-element target's exposed properties is never inferred from attribute value shape — it is expressed only through the explicit `truc:pass={{ ... }}` special attribute (namespaced since LT-053; sub-design 10).

   *(The paragraph that stood here required an explicit authored import for the FactoryContext vocabulary. It was implemented as LT-079 and reversed the same day; sub-design 16 is the standing policy and the reversal's reasoning is in Alternatives. Retained only as this pointer, so the two are not read as concurrent rules.)*

5. **Dual `@for` lowering.** Over server data: rendered once, enhanced via `each()` per-element scopes (ADR [0014](0014-keyed-per-element-scopes-for-memo-collections.md)). Over a reactive `List`: server-rendered keyed items + extracted `<template>` whose holes become `<slot>` markers, reconciled by `reconcile()` (ADR [0017](0017-keyed-template-clone-reconciliation-for-lists.md)). Loop context crosses to the client via **hoisted-const rebinding** (server-data consts rebind to element-derived attribute reads); direct loop-variable references inside reactive thunks are compile errors with a hoist-first diagnostic.
6. **Type flow by emit-then-check, not by editor projection.** The compiler emits its own span-table mappings (generated position → source position) rather than reusing Ripple's `createVolarMappingsResult` — that API is transform-coupled, requiring a source map that covers every token its source-AST visitor walks, an invariant only Ripple's own esrap-shaped transforms satisfy (see Alternatives). Type flow stands on three mechanisms: child-module side-effect imports (every addressed child component's types are in scope), a `globals.d.ts` contract backing the compiler's internal typing for the recognized FactoryContext vocabulary — ambient for authors too, with real-export usage declared via explicit imports (sub-design 16), and `tsc` emit-then-check in CI over both generated client and server modules, remapped through the span table. Sparse mappings suffice — TS diagnostics only arise in code positions, and every code position lowers into a generated module. In-editor (Volar) diagnostics are a later stage over the same span table (LT-014), not a blocker.
7. **Library boundary unchanged.** The compiler is separate build-time tooling; `@zeix/le-truc` stays browser-only and never renders initial HTML — the generated client enhances, and `reconcile()` remains the only DOM-creation primitive. This realizes §7's anticipated companion project as build-time compilation, not a server runtime.
8. **Extension activation via `export const config`.** A `.tsrx` source declares `defineComponent`'s third argument as a zero-import, statically-analyzable data object — `export const config = { formAssociated: true, observedAttributes: ['value'] }`. The compiler validates keys against the known bundled extensions (unknown key, non-`true` form flag, combined form variants → TSRX009), and every `observedAttributes` name must be a Parser-exposed prop. The generated client auto-imports the extension factories from `@zeix/le-truc` and emits them as the third argument with the form variant leading — ADR [0019](0019-extension-based-dependency-injection-for-definecomponent.md)'s ordering rule is enforced structurally, since there is no authored order to get wrong. Attribute-driven props use Parser-call `expose()` initializers (`expose({ value: asString('') })`): the host attribute seeds the prop at connect (ADR [0003](0003-attributes-drive-state-at-connect-time-only.md)) and `observedAttributes` re-parses it on later mutations. A reactive attribute thunk reading `host.<parserProp>` lowers to `watch(() => host.<prop>, bindProperty(el, attr))` and server-renders from the root attribute's expression — the host attribute is the prop's server truth. Managed form props are written as an ordinary host read — `{host.validationMessage}` lowers to `watch('validationMessage', bindText(el))` and server-renders empty — proving the widened `FormFactoryContext` typing end to end.
9. **CEM generation, staged: plugin now, compiler-direct at v3.** The Custom Element Manifest is generated by `cem analyze` with `@zeix/cem-plugin-le-truc` unchanged. The compiler carries the component JSDoc verbatim above the generated `export default defineComponent(`, and the analyzer globs read the generated clients while the migrated components' hand-written `.ts` twins are excluded (kept as golden-test references). Equivalence is pinned by golden tests: byte-equal for `basic-counter`/`module-tabgroup`, structural for `form-textbox`. **When the migration deletes the last hand-written component (v3), the analyzer+plugin dependency is dropped** in favor of compiler-emitted CEM fragments from the registry, which already holds every input the analyzer needs.
10. **Component composition: PascalCase invocation, explicit `truc:pass={{ }}`.** A capitalized JSX tag bound to an `import` of another `.tsrx` module composes that component: the parent's generated server module imports the child's `render<Name>(args): string` and splices its output inline; top-level JSX attributes on a composed element are **server args** (typed parameters of the child's function, passed verbatim). `truc:pass={{ prop: thunk | { get, set } }}` is the sole channel for client-side signal interop with a custom-element target, composed or raw dashed tag alike, lowering to `pass(target, {...})` (ADR [0011](0011-throw-on-pass-binding-failure.md), ADR [0012](0012-deprecate-unrestricted-write-short-forms-in-pass.md)). A JSX prop name can appear once as a server arg and once inside `truc:pass={{ }}` without collision — the two are syntactically disjoint by construction. `ref={name}` only supplies the query variable's name; absent `ref`, `pass`'s target is auto-addressed by the existing selector-synthesis pass (`resolveSelector`/`addQuery`). Two-way `pass()` (`{ get, set }` descriptor entries) is fully wired in codegen. Children compose via one reserved parameter: a composed element's children become the child's `children` function parameter, and the child's template marks the insertion point with a bare `{children}` expression (React's convention), rendered unescaped since it is already-rendered, compiler-trusted HTML — not the `<slot>` element, which is a real DOM tag that would collide with authored Declarative Shadow DOM markup. A required child with no children supplied is a compile-time type error on the generated composed call. `check:tsrx` type-checks generated server modules as well as client modules, since composition is the first construct where server modules import each other's real types.
11. **Optional element references: a non-throwing `first()` under a presence guard** (widened 2026-08-30, LT-123). Optionality has two sources and the compiler takes the WEAKER of them.

   *Site-inferred:* a single-branch `@if` (no `@else`) addresses its root as a `'maybe'`-cardinality query (`first(selector)`, no throw); every effect the branch owns — reactive attributes, events, the managed-prop watch, and any bare client-only statement sitting beside the element — is wrapped in one generated `if (query) { … }` block, client-side. `@if` *with* `@else` keeps union addressing (`'one'` cardinality, since some branch always renders); a bare client-only statement inside a branch that has an `@else` is rejected, since union addressing requires identical constructs in every branch. Branch-root selector synthesis validates uniqueness against the whole template, not just the branch's own subtree.

   *Author-declared:* `first('span.label')` — one selector literal, no reason string — is the optional form, yielding `T | undefined`. Two literals (`first('button', 'Add a native button as descendant.')`) is the required form, throwing the authored reason. This is a new authoring surface onto the machinery above, not new machinery: the same `'maybe'` query, the same guard block, whatever the site looks like.

   The two combine by weakening, never by strengthening, and this is the load-bearing rule. **The template proves what a component RENDERS; it never proves what the component will FIND.** A page may enhance markup this component did not render — a bare `<button>` with no `span.label`, an author's own class list — so a one-literal ref matching an element the template emits unconditionally stays optional. Correspondingly, structural verification (the selector must resolve against the owned template) is enforced for REQUIRED refs only: an optional ref may legitimately address markup the template says nothing about. And because a template-owning component controls its own markup, a required-reason string only earns its keep on a selector that may match markup the component did not itself render — supplied on a ref whose only match sits in a branch that may not render, it can never be thrown, and warns.

   An optional ref's PRESENCE is server-known (LT-118): the server settles it from the `@if` conditions on the path to the matched element, so `hidden={() => Boolean(zeroSpan) && …}` renders an initial value rather than being omitted. A ref read as a MEMBER (`zeroSpan.textContent`) is not — a presence guard is a boolean, not the element — and that thunk is omitted as usual.

   The `@{ }` output is a bare root element or a fragment; the fragment exists to carry a `<style>` beside the root, so a component with no styles has nothing to wrap. A control-flow arm's body is STATEMENT context, not JSX children: `@else { + }` is a parse error and `@else { <>+</> }` is not, a grammar fact of the pinned parser rather than a profile restriction.

12. **A signal's client harvest may substitute more than one arg identifier, traced to any descendant's rendered attribute.** The arg→DOM-site substitution mechanism (LT-008) traces each arg used only to compute a value — never rendered verbatim anywhere — to a plain attribute site the client can read back from at connect time: any descendant's attribute, not only the root's, and several distinct arg identifiers per initializer, not only one. The initializer itself stays a single, unconditional top-level call to a recognized constructor (`createCell`/`deriveCell`/…); conditional logic belongs inside the callback body, not as a choice between constructor calls.
13. **Async boundaries: `@try`/`@pending`/`@catch` route on `isPending(signal)`, all three arms server-rendered and `hidden`-toggled.** A `@pending` arm makes the block a fundamentally different shape from the plain sync error boundary (unchanged, still mutually exclusive): the guarded signal is discovered as a direct lazy child of the `@try` body (`{data}`), not a new discriminant syntax. Server render is synchronous and never awaits: `isPending(data)` picks a tri-state (`'pending' | 'ok' | 'err'`) without invoking an async compute function synchronously; `{ initial }` present seeds `ok` directly, absent means pending. All three arms render unconditionally, the non-matching two `hidden` — mirroring `module-lazyload.ts`'s hand-written shape rather than inventing server-only rendering. Client: one `watch(signal, { ok, err, nil })` call toggles the same three roots' `hidden` going forward — pure enhance, zero client DOM creation.
14. **Import-placement inference for plain (non-`.tsrx`) imports (LT-034).** Only `ImportDeclaration`s resolving to sibling `.tsrx` files are recognized (sub-design 10's compose imports); every other import is silently dropped from generated output — undiscovered until a component needed setup-code helpers from an ordinary library or local utility module (`card-colorscale`'s color math). Decision: the compiler classifies each plain import's bindings by where their free-identifier usages actually occur, reusing the free-identifier/server-known analysis it already runs for setup consts (the `CLIENT_ONLY_PRIMITIVES`/`clientSetup` gate, `ctx.serverKnown`) — no manual per-import annotation, consistent with sub-design 4's "no marker identifiers" stance. An import used only inside server-evaluated positions (`deriveCell`/`createCell` initializers, `@if` conditions, plain setup consts flowing into server-known values) is re-emitted into the server module only; used only inside client-only contexts (reactive attribute thunks, event handlers, `style-map`/`class-map` thunks, lazy children, client-only setup statements) is re-emitted into the client module only; used in both is emitted into both, verbatim. Placement is inferred, never declared: `culori/fn`'s `formatCss`/`getStepColor`, used only inside a `style={() => ({...})}` thunk recomputed from a live prop, land client-only; a syntax highlighter used only inside a server-rendered `html={...}` position would land server-only.
15. **Context protocol support — `requestContext`/`provideContexts` (LT-035, [REQUIREMENTS.md M10](../REQUIREMENTS.md#m10-context-protocol)).** `.tsrx` had zero context-protocol support — `requestContext` wasn't a recognized signal constructor or ambient, so a bare setup statement calling it was rejected outright — undiscovered until a component needed to consume ancestor-provided context (`card-mediaqueries`'s four OS-preference contexts). Decision: full protocol support, both directions, depending on sub-design 14 for importing the plain-`.ts`-module `Context` object definitions (e.g. `MEDIA_MOTION`) into `.tsrx` sources. Consumer side: `requestContext(Context, fallback)` is a new recognized call form, treated like a signal constructor for downstream lowering — its result supports `.get()`, usable in reactive attrs/lazy text exactly like `createCell`/`deriveCell` results. Server rendering has a context-specific rule: since `fallback` is server-known (a literal or simple server-evaluable expression), the server renders using it as the signal's initial value — DOM-is-truth extended, client corrects away from the fallback once the real ancestor-provided context resolves, the same accepted flash-risk tradeoff sub-design 3 already documents for other non-server-known thunk attributes. Provider side: `provideContexts([...])` joins the recognized-ambient-call allowlist alongside `host`/`internals` — a pure connect-time side effect, renders nothing server-side, same treatment as the existing `internals?.states.add(...)` pattern.
16. **Authored imports: real package exports explicit, FactoryContext vocabulary ambient (re-amended 2026-08-27; reverses the same-day explicit-import experiment implemented in LT-079).** The authored vocabulary splits three ways. Real `@zeix/le-truc` exports referenced from `@{ }` setup — signal constructors via the CE bridge (`createCell`/`deriveCell`/…), parsers (`asString`/`asNumber`/…), `defineMethod`, form utilities (`relayValidity`), error classes — are imported explicitly; they are true module exports, so authored sources stay valid TypeScript by construction, ready for whenever a working TSRX language service exists (today's cannot resolve even explicit imports — upstream, out of scope here). The FactoryContext vocabulary authors actually write — `expose`, `first`, `all`, `host`, `internals`, `requestContext`, `provideContexts` — stays ambient through the `globals.d.ts` contract: the factory parameter they arrive on is compiler-generated, so an authored import or destructure for them would be a false declaration. The effect machinery — `watch`, `on`, `pass`, `each`, every `bind*` — is never authored at all: template syntax lowers to it in generated code, per sub-design 4's no-marker-identifiers stance. The `'@zeix/le-truc'` specifier is a first-class plain-import path riding sub-design 14's usage-based placement (retiring the `'../../../index'` relative-specifier wart), while the generated client keeps synthesizing its own import line for generated-only names (`defineComponent`, `bind*`, …). The compiler errors when a real export is used without its import (scope-aware, so a local shadowing the name is not misread) and when a FactoryContext name appears in an authored `'@zeix/le-truc'` import (remove-it fix-it — it is not an export and would break the re-emitted import); unused imports are flagged by the existing plain-import warning (TSRX014).

## Alternatives Considered

- **Status quo (hand-written trio)**: rejected — the drift problem is the motivation; runtime contract errors are the tax.
- **Option B — TSRX as server templating only**: rejected — components stay three files; drift unsolved.
- **Option C — authored split (client export alongside the template)**: validated as feasible, rejected as a shipping format — two truths still coexist per component, doubling format maintenance.
- **Compiler-inferred reactivity (taint walk from declared roots)**: rejected — author-declared markers (thunks, `&{ }`) eliminate the inference entirely.
- **`useExtensions([…])` hook inside `@{ }`**: rejected — a directive that never executes anywhere (stripped client-side, shimmed server-side), unlike every other setup statement; it also hands ADR 0019's formAssociated-first ordering back to the author instead of enforcing it structurally.
- **Module-level `export const extensions = [formAssociated(), …]`**: viable, but requires validating arbitrary array-element shapes for no gain over a closed config key space. Rejected as the primary surface.
- **Compiler-emitted CEM fragments as the migration bridge (bypass the analyzer immediately)**: viable, but ~30 hand-written examples still need the analyzer until the migration completes — would mean two extraction implementations kept in parity while the format is still moving. Adopted as the v3 endgame instead (sub-design 9).
- **Reusing `createVolarMappingsResult` for type flow (sub-design 6)**: rejected after a probe — the API throws unless the source map covers every source-AST token, an invariant tied to Ripple's own transform outputs the split compiler can't satisfy through the client module alone. The compiler emits its own span-table mappings instead.
- **Explicit authored imports for FactoryContext helpers (2026-08-27 experiment, implemented same-day as LT-079, reversed before release)**: rejected — the names are not package exports, so the authored import line was a false declaration a future working language service would flag as an error; `.tsrx` sources have no factory-parameter destructuring site to bind them honestly (the compiler generates the factory signature); and the motivating problem — highlighters ignoring `declare global` — proved deeper than import style: Zed's TSRX language service fails to resolve even explicit imports. Ambient `globals.d.ts` remains the mechanism for context vocabulary (sub-design 16); editor experience waits on upstream.
- **An opt-in `enhancer` mode lifting the constraints a harvesting component hits (implemented under LT-117, rejected and removed 2026-08-30)**: rejected. The goal was flexible server-rendered markup with optional branches; the mode reached it by making the component's entire server render the bare host tag (`'<basic-button></basic-button>'`) and requiring the PAGE to hand-author the button — deleting the server half of the isomorphic format to make the client half compile, which is sub-design 1's "no coexistence" abandoned under a flag. It also traded four lifted constraints for four mode-only ones (no function args, tag derived from the function name, no authored template, a single `<style>` only). The re-diagnosis that killed it is the substantive part: of the four diagnostics the mode existed to lift, one did not apply to a template-owning component at all, one was already satisfied by the `@if` spelling (which generates the presence guard on its own), and one merely mis-typed a resolvable reference as required. The actual blocker was in none of them — it was that a render site could serve the server or the client but not both (sub-design 3, LT-122). **A capability gap in the default path is a reason to widen the default path, never to add a mode that exempts a component from it.**
- **Duplicating a harvested prop onto a host attribute so the client has something to bind (LT-092's workaround)**: rejected — it is exactly what the data account's bullet 2 forbids, shipping template and data twice, and it was only ever a symptom of the render-site gap above. A Parser-exposed prop also rendered into an owned site from a same-named arg now warns for the same reason.
- **Inferring `first()` cardinality from the site alone**: rejected — the template proves what a component renders, never what it will find. A page may enhance markup the component did not render, so an author-declared optional reference matching an unconditional element must stay optional; the compiler takes the weaker of the two claims (sub-design 11).
- **JSX instead of TSRX**: rejected — no first-class control flow, no host-owned scoped styles, no shared parser to build on.
- **Shape-inferred `pass()` dispatch (attribute value shape decides server-arg vs. client-prop)**: rejected — ambiguous once a JSX name can be both a server arg (composed elements) and a client prop; explicit `pass={{}}` names the exact runtime call with no shape inference required.
- **`pass={{}}` scoped to composed elements only, old thunk-shape dispatch kept for raw dashed tags**: rejected — two dispatch rules for the same runtime call; one explicit, uniformly-named mechanism is clearer.
- **Reusing the managed-lazy-child precedent (`&{'validationMessage'}`) for children insertion**: rejected — that precedent is a runtime-reactive host-property read; children substitution is compile-time content substitution, and conflating the two would be misleading.
- **`<slot>Fallback</slot>` as the children insertion marker**: rejected — `<slot>` is a real DOM element; an author using Declarative Shadow DOM elsewhere in the same template would collide with a reserved tag name. A bare `{children}` expression reuses the grammar-native `{expr}` position instead.
- **A dedicated `deriveText(template, subs)` primitive for templated reactive text**: rejected as the primary mechanism (sub-design 12) — scopes the fix to one shape (string-template substitution) when the underlying gap is general. Widening the existing arg→DOM-site substitution reaches the same result with a mechanism the compiler already has.
- **Recognizing a conditional choice between two different signal-constructor calls as one signal**: rejected — doubles the harvest-planning logic's cases for no expressive gain, since the identical branching lives inside a single constructor's callback body anyway.
- **Letting a client-only setup const call `first()`/other DOM primitives directly**: rejected — setup text is emitted verbatim into the server render function too; a DOM-primitive-calling const is unconditionally wrong there, not fixable by relaxing one check. The `refStub` null object (LT-121) that lets `expose()`'s argument evaluate harmlessly server-side is not a reversal of this and must not be widened into one: stubbing a reference so that a DOM-derived value renders as empty string trades a build error for a silently wrong page.

## Consequences

**Good:**

- Single source of truth per component; the HTML contract is checked at compile time (root-tag match, selector uniqueness, hoist-rule enforcement) instead of surfacing as `MissingElementError` in the browser.
- Generated client code is exactly today's idiomatic Le Truc — the existing examples corpus doubles as golden-test expectations.
- Fully co-located authoring; runtime semantics match the Solid/Ripple first-pass-then-pinpoint model. Explicit imports name only real package exports (sub-design 16) — the compiler errors when one is used without its import; the FactoryContext vocabulary stays ambient, and the effect machinery (`watch`/`on`/`pass`/`each`/`bind*`) is never authored at all, keeping template syntax the single declaration surface for reactivity. Authored sources are honest TypeScript by construction, ready for whenever a working TSRX language service lands (today's cannot resolve even explicit imports — upstream, out of scope).
- No state payload to hydrate from; pages are correct before JavaScript loads.
- Components compose: a parent invokes a child's compiled render function instead of hand-duplicating its markup.
- A component that harvests its props from its own rendered children needs no host-attribute copy of them: one authored site renders, harvests, and rebinds (sub-design 3). Optional references let it tolerate markup a page authored differently — or not at all — without abandoning server rendering (sub-design 11).

**Bad / accepted tradeoffs:**

- Sub-design 4's explicit `truc:pass={{}}` dispatch means existing raw-tag examples using the old implicit function-valued-attribute form need updating.
- The rewrite rules (hoisted-const rebinding, harvest rules, dual `@for`) are product surface — exhaustive specification and golden tests are mandatory; a wrong rewrite is a wrong component.
- `@tsrx/core` is 0.x and fast-moving: the pin holds, but upgrade churn is expected and reviewed.
- Raw `.tsrx` files are untyped without the projection toolchain; in-editor diagnostics (LT-014) remain the largest residual implementation risk.
- Thunk attributes with non-server-known dependencies render client-corrected (flash risk accepted; authored statics mitigate).
- The examples corpus migrates wholesale — no coexistence path — and authors debug generated factories (mitigated by the DEV_MODE `debug()` extension, ADR 0022).
- Arbitrary JS beyond the sanctioned subset (a conditional choice of signal constructor, a client-only setup const calling DOM primitives directly) stays gated with a named diagnostic, same posture as `@if`/`@switch`/`@try`'s milestone gates.
- The arg-and-prop rule (sub-design 3) fires on a name coincidence and has no opt-out: an author wanting a site rendered once and never rebound cannot say so. Accepted while every corpus site wants the binding; a counterexample reopens it.
- An optional reference turns a missing element into a silent no-op where a required one throws. That is the point — but it means a mis-typed selector fails quietly, so selector synthesis must stay faithful to what the author wrote.
- An async boundary's server render always emits all three arms' markup (sub-design 13) — heavier HTML than a "pick one" render — accepted because `hidden`-toggling is the enhance-don't-render model's posture everywhere else, and matches `module-lazyload.ts`'s existing hand-written shape.
