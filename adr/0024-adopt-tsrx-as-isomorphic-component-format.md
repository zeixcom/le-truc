# ADR 0024: Adopt TSRX as the Isomorphic Component Format

## Status

✅ Accepted — **sub-designs 2 and 3 amended by [ADR 0029](0029-tiered-server-evaluation.md) (2026-09-04)**

ADR 0029 tiers server evaluation: initial HTML is rendered by whichever mechanism the component's tier calls for, not unconditionally by Server Simulation. **Sub-design 1 (template lowering) and sub-design 7 (library boundary) are untouched** — the compiler still lowers every template to markup server-side for every component in every tier, and `@zeix/le-truc` still never renders. Only the *evaluation of reactive initial values* is tiered.

## Context

Every Le Truc component is authored as three hand-maintained files (`.ts` / `.html` / `.css`) whose mutual contract is checked only at runtime — `first()` failures are the symptom, drift is the disease. REQUIREMENTS.md [§1](../REQUIREMENTS.md#the-core-insight) requires server-rendered HTML with a thin reactive enhancement layer, [§5](../REQUIREMENTS.md#5-technical-constraints) prohibits client-side rendering and any SSR layer *in the library*, and [§7](../REQUIREMENTS.md#7-out-of-scope) anticipated a companion project for the server half. TSRX (Ripple ecosystem) is a TypeScript superset with a shared parser (`@tsrx/core`) and per-target codegen; every existing target renders and re-renders its own DOM — Le Truc is the first server-oriented target. Two Phase 0 spikes validated the direction before this ADR: every syntactic position needed is grammar-native, and hand-compiling isomorphic sources reproduces today's hand-written components statement for statement.

## Decision

Adopt an **isomorphic single-file `.tsrx` format** — server args, signals, `expose()`, markup, event handlers, and scoped styles in one source, the single source of truth for both the server render and the client enhancement — compiled by a **split compiler** built in-repo on pinned `@tsrx/core`. Sub-designs:

1. **One format, no coexistence.** The isomorphic format is the only authoring format. No authored-client fallback, no escape hatches; event delegation is a compiler optimization for bubbling events.

2. **Split compiler, isolated dependency.** Per component the compiler emits server markup (template lowering), a generated `defineComponent()` client factory importing solely from `@zeix/le-truc`, verbatim tag-scoped CSS (no class hashing), and a registry entry. Initial HTML is rendered by the mechanism the component's **evaluation tier** calls for (ADR [0029](0029-tiered-server-evaluation.md)): tier 1 folds the reactive graph's initial values in the DOM-less value harness, tier 2 runs **Server Simulation** (ADR [0027](0027-server-simulation.md)) — the driver executes the generated client module against jsdom and serializes the reactive graph's initial state — and tier 0 ships the static skeleton for expressions no phase can resolve, leaving them to the client. The two evaluating mechanisms are kept from drifting by a CI equivalence audit that renders every tier-1 component through the realm as well and requires byte-identical output (ADR 0029 sub-design 7). The emit path is one path with a tier flag: every component gets a server render module, and only tier 1 re-declares `@{ }` setup verbatim. Authored sources import the real `@zeix/le-truc` exports their setup code references (sub-design 16); the FactoryContext vocabulary is ambient, and the effect machinery (`watch`/`on`/`pass`/`each`) is generated, never authored. `@tsrx/core` is pinned behind one emitter module; upgrades are reviewed changes. The compiler is inlined in this repo — no separate package ships before TSRX reaches 1.0; with Le Truc v3.0 may ship as `@tsrx/le-truc` or `@zeix/tsrx-le-truc`, while `@zeix/le-truc` remains the backend-agnostic client layer.

3. **DOM-is-truth seeding, end to end.** The server renders each reactive expression's initial value by its tier's mechanism — folded in the value harness, or by executing the same client module the browser runs (ADR 0027/0029); the client harvests its initial state from that DOM at connect (ADR [0003](0003-attributes-drive-state-at-connect-time-only.md) preserved; no serialized state payload). Lists seed from server args server-side and are adopted from the rendered HTML client-side. The harvest site is canonical — first match in document order; DEV_MODE warns on disagreement. Every thunk renders its best server answer *that some phase can compute* — the omission path survives, narrowed, for tier 0: expressions whose every unresolved read routes through an API the simulation realm itself stubs out (layout geometry, `internals`, absent sensors) are omitted and corrected by the client, because simulating them would return zeros rather than answers (ADR 0029). Values the simulation can only approximate (impure ambient reads, absent APIs) ship the simulated answer and the client corrects on connect — the accepted flash trade, mitigated by authored static markup for the no-JS initial state.

  **One site, three roles.** A prop a component harvests from its own children is rendered into that site from the component's server arg (`<span class="label">{label}</span>`), harvested back out of the same site at connect (`expose({ label: labelSpan?.textContent ?? … })`), and rebound there on later writes — render target, harvest source, and binding target in one authored site. This is what keeps a component from demanding as a host attribute what its owned children already carry. Three exclusions, each for a different reason: declared signals (they own a render site and a harvest plan already), the root element's own attributes (the root IS the host, so a prop rendered there is the channel, not a copy), and Parser-exposed props, whose seeding channel is the host attribute — rendering the same value into an owned site ships it twice and would fight a native control's dirty-value flag, so that shape warns instead of binding.

4. **Author-declared reactivity, no marker identifiers.** On a native element, a function-valued attribute is a reactive DOM binding (`watch()` plus the matching `bind*` helper); `on*`-prefixed attributes are events (stripped from the served markup); a `{expr}` child whose expression reads reactive state is the grammar-native reactive child — reactivity is inferred from what the expression reads, not from a marker. No upstream grammar changes required. Interop with a custom-element target's exposed properties is never inferred from attribute value shape — it is expressed only through the explicit `truc:pass={{ ... }}` special attribute (sub-design 10).

  **ARIA attributes route by target.** A reactive `aria-*` attribute lowers to `bindAria()` (ADR [0026](0026-aria-reflection-via-elementinternals-and-bindaria.md)), not `bindAttribute()` — the helper owns ARIA's coercion (`boolean` → `'true'`/`'false'`, `number` → decimal, `nil` → clear). On a CHILD element the binding is `bindAria(el, '<idlName>')`: native IDL reflection mirrors the write into the content attribute, so the value stays visible to CSS and `getAttribute()`. On the ROOT the binding is `bindAria(internals, '<idlName>')`, per ADR 0026's two-channel policy — and since `bindAria()` on an internals target removes the shadowing content attribute at its first value assertion, a component's own stylesheet may not select the host on an `aria-*` attribute: `:state()` (ADR [0016](0016-element-internals-for-form-association-and-states.md) §8) is the component-owned styling hook, and a violation is a diagnostic. Child ARIA selectors are unaffected. The attribute→IDL mapping is a lookup table derived from `ARIAMixin`, not a casing transform; the eight element-reference properties (`ariaDescribedByElements` and siblings) take `Element`/`Element[]` and are excluded — IDREF ARIA stays on `bindAttribute`.

5. **Dual `@for` lowering.** Over server data: rendered once, enhanced via `each()` per-element scopes (ADR [0014](0014-keyed-per-element-scopes-for-memo-collections.md)). Over a reactive `List`: server-rendered keyed items plus an extracted `<template>` whose holes become `<slot>` markers, reconciled by `reconcile()` (ADR [0017](0017-keyed-template-clone-reconciliation-for-lists.md)). Loop context crosses to the client via hoisted-const rebinding (server-data consts rebind to element-derived attribute reads); a direct loop-variable reference inside a reactive thunk is a compile error with a hoist-first diagnostic.

6. **Type flow by emit-then-check, not by editor projection.** The compiler emits its own span-table mappings (generated position → source position) rather than reusing Ripple's `createVolarMappingsResult` (see Alternatives). Type flow stands on three mechanisms: child-module side-effect imports put every addressed child component's types in scope; a `globals.d.ts` contract backs the compiler's internal typing of the recognized FactoryContext vocabulary, ambient for authors too (sub-design 16); and `tsc` emit-then-check runs in CI over both generated client and server modules, remapped through the span table. Sparse mappings suffice — TS diagnostics only arise in code positions, and every code position lowers into a generated module. In-editor (Volar) diagnostics are a later stage over the same span table.

7. **Library boundary unchanged.** The compiler and the simulation driver are build-time tooling; `@zeix/le-truc` stays browser-only and never renders initial HTML — the generated client enhances, and `reconcile()` remains the only DOM-creation primitive. jsdom never ships to clients (ADR 0027). This realizes §7's anticipated companion project as build-time compilation, not a server runtime.

8. **Extension activation via `export const config`.** A `.tsrx` source declares `defineComponent`'s third argument as a zero-import, statically analyzable data object — `export const config = { formAssociated: true, observedAttributes: ['value'] }`. The compiler validates keys against the known bundled extensions (unknown key, non-`true` form flag, combined form variants → TSRX009), and every `observedAttributes` name must be a Parser-exposed prop. The generated client auto-imports the extension factories and emits them as the third argument with the form variant leading — ADR [0019](0019-extension-based-dependency-injection-for-definecomponent.md)'s ordering rule is enforced structurally, since there is no authored order to get wrong. Attribute-driven props use Parser-call `expose()` initializers (`expose({ value: asString('') })`): the host attribute seeds the prop at connect (ADR 0003) and `observedAttributes` re-parses it on later mutations. A reactive attribute thunk reading `host.<parserProp>` lowers to `watch(() => host.<prop>, bindProperty(el, attr))`; managed form props are written as ordinary host reads — `{host.validationMessage}` lowers to `watch('validationMessage', bindText(el))` — proving the widened `FormFactoryContext` typing end to end.

9. **CEM generation, staged: analyzer now, compiler-direct at v3.** The Custom Element Manifest is generated by `cem analyze` with `@zeix/cem-plugin-le-truc`; the analyzer globs read the generated clients (the compiler carries component JSDoc verbatim above `export default defineComponent(`) while the migrated components' hand-written `.ts` twins are excluded but kept as golden-test references. Equivalence is pinned by golden tests: byte-equal for `basic-counter`/`module-tabgroup`, structural for `form-textbox`. When the migration deletes the last hand-written component (v3), the analyzer+plugin dependency is dropped in favor of compiler-emitted CEM fragments from the registry, which already holds every input the analyzer needs.

10. **Component composition: PascalCase invocation, explicit `truc:pass={{ }}`.** A capitalized JSX tag bound to an import of another `.tsrx` module composes that component: the parent's server render includes the child's rendered markup, with the simulated connect resolving composition against the real child element (ADR 0027); top-level JSX attributes on a composed element are the child's server args (typed parameters of the child's function), passed verbatim. `truc:pass={{ prop: thunk | { get, set } }}` is the sole channel for client-side signal interop with a custom-element target, composed or raw dashed tag alike, lowering to `pass(target, {...})` (ADR [0012](0012-deprecate-unrestricted-write-short-forms-in-pass.md), ADR [0028](0028-tiered-error-surfacing.md)); a JSX prop name can be both a server arg and a `truc:pass` entry without collision — the two are syntactically disjoint by construction. A compose site is addressed the same way a raw one is — `first('<child-tag>.<discriminator>')` in setup — resolved in the registry-aware second pass, which attaches the same synthetic ref IR the raw path attaches. `class`/`id` on a compose site are spliced onto the child's rendered root and therefore reach the served DOM — the only way to tell two same-source compose sites apart. Children compose via one reserved parameter: a composed element's children become the child's `children` function parameter, and the child's template marks the insertion point with a bare `{children}` expression (React's convention), rendered unescaped as compiler-trusted HTML — not the `<slot>` element, which is a real DOM tag that would collide with authored Declarative Shadow DOM markup. A required child with no children supplied is a compile-time type error. `check:tsrx` type-checks generated server modules as well as client modules, since composition is the first construct where server modules import each other's real types.

11. **Optional element references: a non-throwing `first()` under a presence guard.** Optionality has two sources and the compiler takes the WEAKER of them. *Site-inferred:* a single-branch `@if` (no `@else`) addresses its root as a `'maybe'`-cardinality query (`first(selector)`, no throw); every effect the branch owns — reactive attributes, events, the managed-prop watch, any bare client-only statement beside the element — is wrapped in one generated `if (query) { … }` block, client-side. `@if` *with* `@else` keeps union addressing (`'one'` cardinality, since some branch always renders); a bare client-only statement inside a branch that has an `@else` is rejected, since union addressing requires identical constructs in every branch. Branch-root selector synthesis validates uniqueness against the whole template, not just the branch's own subtree. *Author-declared:* `first('span.label')` — one selector literal, no reason string — is the optional form, yielding `T | undefined`; two literals (`first('button', 'Add a native button as descendant.')`) is the required form, throwing the authored reason. One authoring surface onto the existing machinery, not new machinery. **The template proves what a component RENDERS; it never proves what the component will FIND.** A page may enhance markup this component did not render, so an author-declared optional reference matching an unconditionally rendered element stays optional; structural verification (the selector must resolve against the owned template) is enforced for required refs only. A required-reason string only earns its keep on a selector that may match markup the component did not itself render — supplied on a ref whose only match sits in a branch that may not render, it can never be thrown, and warns. An optional ref's presence has a server answer by construction: the simulation executes the same guards the browser will, so a thunk reading a ref renders an initial value rather than being omitted (ADR 0027). The `@{ }` output is a bare root element or a fragment; the fragment exists to carry a `<style>` beside the root, so a component with no styles has nothing to wrap. A control-flow arm's body is STATEMENT context, not JSX children — `@else { + }` is a parse error and `@else { <>+</> }` is not, a grammar fact of the pinned parser.

12. **A signal's client harvest may substitute several arg identifiers, traced to any descendant's rendered attribute.** The arg→DOM-site substitution traces each arg used only to compute a value — never rendered verbatim anywhere — to a plain attribute site the client can read back from at connect: any descendant's attribute, and several distinct arg identifiers per initializer. The initializer stays a single, unconditional top-level call to a recognized constructor (`createCell`/`deriveCell`/…); conditional logic belongs inside the callback body, not as a choice between constructor calls.

13. **Async boundaries: `@try`/`@pending`/`@catch` route on `isPending(signal)`.** The guarded signal is discovered as a direct lazy child of the `@try` body (`{data}`) — no new discriminant syntax. All arms render, the non-shipped ones `hidden`; one `watch(signal, { ok, err, nil })` toggles them on the client — pure enhance, zero client DOM creation. Which arm the served HTML shows is a compiler decision inside the simulation's hermetic quiescence window: the resolved arm ships only when its value is harvestable from the markup the component itself rendered (seeding the client task from that markup); otherwise `@pending` ships (ADR 0027). The plain synchronous `@try`/`@catch` error boundary (no `@pending`) stays a separate, mutually exclusive shape; its arms render into isolated buffers so a mid-arm throw cannot leak partial markup.

14. **Import placement is inferred for plain imports, never declared.** Only import declarations resolving to sibling `.tsrx` files are compose imports (sub-design 10); every other import is classified by where its bindings' free-identifier usages occur — reusing the usage analysis the compiler already runs — and re-emitted verbatim into the module or modules that need them. Consistent with sub-design 4's no-marker stance: a syntax highlighter used only inside a `truc:html` thunk lands where that thunk evaluates; color math used only inside a `style={() => …}` thunk lands client-only.

15. **Context protocol support: `requestContext`/`provideContexts`.** `requestContext(Context, fallback)` is a recognized signal-constructor form: its result supports `.get()` and is usable in reactive attributes and lazy text exactly like `createCell`/`deriveCell` results. `provideContexts([...])` joins the recognized ambient-call allowlist alongside `host`/`internals` — a pure connect-time side effect that renders nothing. The server renders the `fallback` (a literal or simple server-evaluable expression) as the signal's initial value; the client corrects away from it once the real ancestor-provided context resolves — the same accepted flash trade as sub-design 3, and the fallback-render precedent ADR 0027 preserves. Context object definitions (`MEDIA_MOTION`, …) are plain-`.ts` imports riding sub-design 14.

16. **Authored imports: real package exports explicit, FactoryContext vocabulary ambient.** Real `@zeix/le-truc` exports referenced from `@{ }` setup — signal constructors (via the Cause & Effect bridge), parsers (`asString`/`asNumber`/…), `defineMethod`, form utilities (`relayValidity`), error classes — are imported explicitly: they are true module exports, so authored sources stay valid TypeScript by construction. The FactoryContext vocabulary authors write — `expose`, `first`, `all`, `host`, `internals`, `requestContext`, `provideContexts` — stays ambient through the `globals.d.ts` contract: the factory parameter they arrive on is compiler-generated, so an authored import for them would be a false declaration. The effect machinery — `watch`, `on`, `pass`, `each`, every `bind*` — is never authored at all: template syntax lowers to it (sub-design 4). The `'@zeix/le-truc'` specifier is a first-class plain-import path riding sub-design 14's placement, while the generated client keeps synthesizing its own import line for generated-only names (`defineComponent`, `bind*`, …). The compiler errors when a real export is used without its import (scope-aware, so a local shadow is not misread) and when a FactoryContext name appears in an authored `'@zeix/le-truc'` import (it is not an export); unused imports warn (TSRX014).

## Alternatives Considered

- **Status quo (hand-written trio)**: rejected — the drift problem is the motivation; runtime contract errors are the tax.
- **Option B — TSRX as server templating only**: rejected — components stay three files; drift unsolved.
- **Option C — authored split (client export alongside the template)**: validated as feasible, rejected as a shipping format — two truths still coexist per component, doubling format maintenance.
- **Compiler-inferred reactivity (taint walk from declared roots)**: rejected — author-declared thunks eliminate the inference entirely.
- **`useExtensions([…])` hook inside `@{ }`**: rejected — a directive that never executes anywhere (stripped client-side, shimmed server-side), unlike every other setup statement; it also hands ADR 0019's formAssociated-first ordering back to the author instead of enforcing it structurally.
- **Module-level `export const extensions = [formAssociated(), …]`**: viable, but requires validating arbitrary array-element shapes for no gain over a closed config key space.
- **Compiler-emitted CEM fragments as the migration bridge**: viable, but the remaining hand-written corpus needs the analyzer until the migration completes — two extraction implementations kept in parity while the format is still moving. Adopted as the v3 endgame instead (sub-design 9).
- **Reusing `createVolarMappingsResult` for type flow (sub-design 6)**: rejected after a probe — the API throws unless the source map covers every source-AST token, an invariant tied to Ripple's own transform outputs. The compiler emits its own span-table mappings instead.
- **Explicit authored imports for FactoryContext helpers**: rejected — the names are not package exports, so the import line is a false declaration a working language service would flag, and `.tsrx` has no factory-parameter site to bind them honestly. Ambient `globals.d.ts` stands (sub-design 16).
- **A binary "phase 1 cannot resolve it, therefore simulate it" routing rule**: rejected on measurement — it sends the corpus's largest cost driver (`module-scrollarea`, 2,091 occurrences) into a realm whose own stub posture guarantees a null answer. ADR 0029's three-tier classifier asks whether simulation is *worth* running, not merely whether folding failed.
- **An opt-in `enhancer` mode exempting a component from default-path constraints**: rejected — it deleted the server half of the isomorphic format to make the client half compile (sub-design 1 abandoned under a flag), and the diagnostics it existed to lift were not the real blocker. **A capability gap in the default path is a reason to widen the default path, never to add a mode that exempts a component from it.**
- **Duplicating a harvested prop onto a host attribute so the client has something to bind**: rejected — it ships template and data twice, exactly what the one-site-three-roles rule forbids; a Parser-exposed prop also rendered into an owned site warns for the same reason.
- **Inferring `first()` cardinality from the site alone**: rejected — the template proves what a component renders, never what it will find; the compiler takes the weaker of the two claims (sub-design 11).
- **JSX instead of TSRX**: rejected — no first-class control flow, no host-owned scoped styles, no shared parser to build on.
- **Shape-inferred `pass()` dispatch, or `pass` scoped to composed elements only**: rejected — ambiguous once a JSX name can be both a server arg and a client prop, and two dispatch rules for the same runtime call; one explicit, uniformly named mechanism is clearer.
- **Reusing the managed-lazy-child precedent for children insertion**: rejected — that precedent is a runtime-reactive host-property read; children substitution is compile-time content substitution, and conflating the two would be misleading.
- **`<slot>Fallback</slot>` as the children insertion marker**: rejected — `<slot>` is a real DOM element; Declarative Shadow DOM markup elsewhere in the same template would collide. A bare `{children}` reuses the grammar-native `{expr}` position instead.
- **A dedicated `deriveText(template, subs)` primitive for templated reactive text**: rejected as the primary mechanism — it scopes the fix to one shape when the underlying gap is general; widening arg→DOM-site substitution reaches the same result with existing machinery (sub-design 12).
- **Recognizing a conditional choice between two signal-constructor calls as one signal**: rejected — doubles the harvest-planning logic's cases for no expressive gain, since the identical branching lives inside a single constructor's callback body anyway.

## Consequences

**Good:**

- Single source of truth per component; the HTML contract is checked at compile time (root-tag match, selector uniqueness, hoist-rule enforcement) instead of surfacing as `MissingElementError` in the browser.
- Generated client code is exactly idiomatic Le Truc — the examples corpus doubles as golden-test expectations.
- Fully co-located authoring; runtime semantics match the Solid/Ripple first-pass-then-pinpoint model. Authored sources are honest TypeScript by construction (sub-design 16), keeping template syntax the single declaration surface for reactivity.
- No state payload to hydrate from; pages are correct before JavaScript loads.
- Components compose — a parent invokes a child's compiled render instead of hand-duplicating its markup — and under simulation a composing parent's connect-time reads see its children's reactive state (ADR 0027).
- A component that harvests its props from its own rendered children needs no host-attribute copy of them: one authored site renders, harvests, and rebinds (sub-design 3). Optional references let it tolerate markup a page authored differently — or not at all — without abandoning server rendering (sub-design 11).
- Element references are executed against the served markup, not merely structurally checked, so ref drift is build-caught by construction (ADR 0027).

**Bad / accepted tradeoffs:**

- The rewrite rules (hoisted-const rebinding, harvest rules, dual `@for`) are product surface — exhaustive specification and golden tests are mandatory; a wrong rewrite is a wrong component.
- `@tsrx/core` is 0.x and fast-moving: the pin holds, but upgrade churn is expected and reviewed.
- Raw `.tsrx` files are untyped without the projection toolchain; in-editor diagnostics remain the largest residual risk, waiting on upstream language-service work.
- Thunk values the simulation can only approximate (layout reads, absent APIs) render client-corrected — the flash trade is accepted, and the fixture-pinned corpus is the guard (ADR 0027). Under ADR 0029 those components are routed to tier 0 rather than simulated, so the build stops paying for an answer it will not get; the served HTML is the same either way.
- Two evaluation mechanisms coexist (value harness and realm), which ADR 0027 had eliminated. The CI equivalence audit is what keeps them from drifting and is a standing obligation, not an optimization (ADR 0029).
- The examples corpus migrates wholesale — no coexistence path — and authors debug generated factories (mitigated by the DEV_MODE `debug()` extension, ADR [0022](0022-debug-extension-for-visual-and-console-instrumentation.md), and ADR 0028's tiered error surfacing).
- Arbitrary JS beyond the sanctioned subset (a conditional choice of signal constructor) stays gated with a named diagnostic, same posture as `@if`/`@switch`/`@try`'s milestone gates.
- The arg-and-prop rule (sub-design 3) fires on a name coincidence and has no opt-out: an author wanting a site rendered once and never rebound cannot say so. Accepted while every corpus site wants the binding; a counterexample reopens it.
- An optional reference turns a missing element into a silent no-op where a required one throws. That is the point — but it means a mis-typed selector fails quietly, so selector synthesis must stay faithful to what the author wrote.
- An async boundary's server render emits all arms' markup — heavier HTML than a pick-one render — accepted because `hidden`-toggling is the enhance-don't-render model's posture everywhere else.
