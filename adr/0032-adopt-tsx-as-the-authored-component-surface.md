# ADR 0032: Adopt `.tsx` as the Authored Component Surface

## Status

🔄 Proposed — spike verdict **GO** (LT-183, `spike/tsx/FINDINGS.md`); execution (corpus migration, profile hardening) pending tasking.

## Context

ADR [0024](0024-adopt-tsrx-as-isomorphic-component-format.md) adopted `.tsrx` — a bespoke grammar on pinned `@tsrx/core` 0.1.x — as the authoring surface for the isomorphic single-file format. The 2026-09-06 architecture review split that compiler into **machinery** (tiered server evaluation, harvest, analysis, emitters, simulation — format-independent, ~10k of ~17k lines) and **surface** (the grammar, its parser pin, and everything the grammar's JSX-adjacency costs: the TSRX021–024 React near-miss family, the `className`/`htmlFor` rename table, broken editor support, span tables + emit-then-check remapping so `tsc` can check authored code at all). The LT-183 spike (TSX_SPIKE.md) re-targeted the front end onto the `typescript` package's own parser (`ScriptKind.TSX`) and measured parity: all four ported components render **byte-identical** server output and CSS through the unmodified machinery; the corpus's two Simulated-tier components match through the unmodified `sim/` realm; a deliberate compose-site type error is reported by plain `tsc` **on the authored parent file**; both hard control-flow shapes (async boundary, statement arms/loops) have workable spellings through the unmodified analysis. REQUIREMENTS [§5](../REQUIREMENTS.md#5-technical-constraints) (no client-side rendering, no SSR in the library) and [§7](../REQUIREMENTS.md#7-out-of-scope) are untouched: this is an authoring-surface swap; every shipped library contract and the whole machinery layer are identical.

## Decision

Re-target the compiler front end from `.tsrx` to standard **`.tsx`**, parsed by the repo's `typescript` dependency (^6.0.3) via `ts.createSourceFile(..., ScriptKind.TSX)` and lowered through a small TS→estree converter so every downstream stage (`ComponentIR` consumers: `analysis/*`, both emitters, `tier.ts`, `sim/`) is reused **unmodified**. Sub-designs (superseding ADR 0024's surface sub-designs **1, 4, 6, 14** and amending **16**; 0024's 3, 5, 7–13, 15 carry over unchanged):

1. **Module shape.** One exported component function per file: its single destructured parameter is the server args (types flow to compose sites for free — see 3); statements before the single `return` are the setup (the `@{ }` block's replacement); the returned JSX — bare root element or fragment — is the template; a `<style>` sibling inside the fragment carries the CSS as a **template-literal child** (`<style>{`…`}</style>`): JSX text cannot contain raw CSS braces. `export const i18n` / `export const config` / type declarations / `declare global` carry over unchanged. The `{count}` attribute shorthand spells `count={count}` (identical server-attr IR).

2. **Control flow as expressions (§5 of TSX_SPIKE.md, proven).** `{c ? <a/> : <b/>}` / `{c && <a/>}` → `if`; `{xs.map((x, i) => …)}` → `for` (over server data `each()`, over a declared `createList` the `reconcile()` path — the dual lowering stays the analysis's decision, keyed by iterable type, not spelling; the `key k` clause retires, keyed by the list's own `keyConfig`); `@switch` → an IIFE around a statement `switch` returning JSX per arm; the plain error boundary → a try/catch IIFE; the async boundary → the recognized ambient `boundary({ ok, pending, err })` call — all three arms render, which ships stays the compiler decision it was. **Statement-context arms and bare `client-stmt` inside a branch retire with the grammar** (unexpressible in child position; 0024 s11 already restricted them) — statements live in setup.

3. **Authored sources are type-checked directly; the span-table detour retires for authored code.** The spike tsconfig sets `jsx: preserve` (authored files are never emitted by `tsc`; generated modules keep their own check path for generated-code diagnostics). TS 6 type-checks namespaced JSX attribute names per element, so `truc:pass` / `truc:case` / `truc:case-type` survive verbatim AND become type-checkable: the ambient `JSX.IntrinsicElements` host profile declares the light-DOM surface per element (`class`/`for`, function-valued thunk overloads — `className`/`htmlFor` simply have no entry, so the React prior produces a plain tsc error and the TSRX021–024 family, `REACT_ATTR_RENAMES`, and `scripts/codemod-react-jsx.ts` are deleted). A composed child declares its compiler-consumed pass surface on its args type (`'truc:pass'?: { filter?: () => string }`) so a parent's `truc:pass={{ … }}` checks against the child's real shape; compose type errors surface on the authored parent (pinned by the spike's negative test). Span tables + remapping survive only for **generated** modules.

4. **Parser boundary.** `typescript` replaces the `@tsrx/core` pin: `core.ts`, `core-shim.d.ts`, `newerGrammarHint`, and pin-upgrade reviews are deleted. The front end keeps one-module boundary discipline (the converter is the only `typescript`-API leaf; oxc-parser stays a future swap behind it — rejected now for recreating the pinned-0.x-parser situation). No Babel anywhere: the transform is source-to-source, emitting the same artifact classes as today; JSX semantics never execute.

5. **Machinery boundary (the spike's thesis, now evidence).** `server/tsrx/`'s `analysis/*`, `emit-server.ts`, `emit-client.ts`, `runtime.ts`, `sim/*`, `evaluability.ts`, `reactivity.ts`, `tier.ts`, `first-refs.ts`, and `imports.ts` are reused **byte-identical** — the spike changed zero lines there. ADR 0024 s2's packaging gate ("no separate package before TSRX reaches 1.0") dissolves: the standalone core ships with no upstream dependency; a Vite adapter comes at packaging time (Bun stays primary; adapters are thin and last).

**Measured ledger (LT-183).** New front end: 3,335 lines — 747-line TS→estree converter (new; work the pinned parser used to do upstream), ~950 verbatim-copied from `compiler.ts`/`lower-template.ts` (a production merge extracts the shared setup-extraction loop and element lowering into shared modules, deleting the copies → projected ≈2.4k), ~430 adapted, plus the 104-line host profile. Replaced: 3,413 direct front-end lines (`compiler.ts`, `lower-template.ts`, `classify-attributes.ts` — reused verbatim in the spike — `core.ts`, `core-shim.d.ts`) and ~2k of tooling/diagnostic surface (TSRX018/020/021–024 families, codemod, authored-code span remap) — the ~5.4k format-specific layer of the spike plan.

## Alternatives Considered

- **Keep `.tsrx`** (the NO-GO path): retains the upstream-parser bet and the near-miss diagnostics; forfeits direct tsc checking of authored sources and working editors. The spike now has counter-evidence on every claimed cost of switching.
- **oxc-parser** instead of `typescript`: fast, but 0.x with an evolving API — recreates the pinned-parser boundary problem ADR 0024 just paid to contain.
- **Babel transform**: structurally avoided (§2.3 of the spike): the concern was buying a transform step that does not fit server-rendered HTML; the chosen pipeline changes no artifact classes.

## Consequences

**Good:** editors work through plain tsserver (LT-014 retires as moot); the React JSX prior becomes *correct* instead of diagnosed; compose type-flow runs through real parameter types with errors on the authored file; the format-specific layer shrinks (~5.4k → ~3.3k measured, ≈2.4k projected) and loses its upstream dependency entirely; attribute/internationalization/reactivity semantics and every shipped contract are unchanged (byte-identical renders proven across all three tiers' mechanisms); `TSRX-HOST-PROFILE.md` becomes the `.tsx` host profile (ambient vocabulary + `IntrinsicElements` surface).

**Bad:** grammar-native statement arms are gone (ternaries/`&&`/IIFEs instead — ergonomics loss, measured acceptable on the corpus's shapes); `boundary({ … })` is host vocabulary an author must learn; CSS requires template-literal wrapping inside `<style>`; the `{count}` shorthand is gone; TS 6.0 renamed AST members (`IfStatement.thenStatement`, `isSequenceExpression`/`isAssignmentExpression`/`isJsxMemberExpression` dropped from the d.ts) — the converter must track the `typescript` major, the same discipline the old pin had but at a slower-moving target; 22 corpus components migrate (one mechanical codemod pass, spike-fixtures-shaped).
