**Area:** compiler
**Changed:** ADR 0048 s2, the child side of the children contract. `Children<Roles, Model>` (`src/component.ts`, exported from the package entry and `types/`) is a type-only branded string, so `children = ''` and `children?: string` sources keep compiling. Under the typed factory context, `first('.tab')`/`all('.tab')` type as the declared role's tag. The compiler reads roles and model from the `children` annotation (inline or same-file alias) onto the IR as `childrenContract`. **LTC083** (tier 1 Prevented): a declared `first()` reference that matches nothing in the child's own template, in a template that inserts `{children}`, whose subject compound names no declared role class, fails the compile, at both verification sites. A role-addressed reference in an inserting template compiles required or optional: queried from the host through the region re-include, and a required one throws `MissingElementError` with the authored reason when the parent passes no such element. Without an insertion the plain handling applies (required → LTC026). An unreadable roles declaration (imported `Children` alias or roles name) gets LTC083 copy naming the readable shapes. The check covers declared `const x = first(…)` references only; inline `first()`/`all()` calls and `all()` declarations are not verified (module-cem-list, LT-513). Docs: HOST_PROFILE, LE_TRUC_COMPILER, VOCABULARY_LEDGER, `errors.md`.

Accepted as is: no `related` range to the annotation, one LTC083 code for both copies, intersections like `Children<…> & string` reading as no contract, an undeduplicated required query.
