**Area:** compiler
**Changed:** ADR 0048 s3, one writer per property. **LTC084** (tier 1 Prevented, compiler, both surfaces) fails a parent `watch` binding on a `first()` reference into a compose site's content when it writes the same thing as the child on an element carrying one of the child's role classes. The report lands at the parent's binding and names both writers.
- **The child's half:** the registry entry gains `roleWrites`, keyed per role. It records what the child's role-targeted `watch` bindings write (`bindProperty`, `bindAttribute`, `bindText`, `bindClass`, `bindVisible`, `bindStyle`, `bindAria`). A reference that matched the child's own template records nothing, and so does one in a template with no `{children}` insertion.
- **Matching:** property and attribute writes compare by their attribute spelling: ARIA properties as `aria-` plus the lowercase rest, `className`→`class`, `htmlFor`→`for`, everything else lowercased. A whole-attribute write (`class`, `style`, `textContent`/`innerText`/`innerHTML`) conflicts with any token, style property or text write of its kind, in both directions.
- **Not checked:** `on()` return updates (they write host props), computed name arguments, and hand-authored pairings (no registry).
- **Code:** `server/compiler/analysis/role-writes.ts`.
- **Docs:** HOST_PROFILE, LE_TRUC_COMPILER, VOCABULARY_LEDGER, `skills/le-truc/references/errors.md`, the `Children` JSDoc in `src/component.ts`.

**Review:** Approved (2026-10-09) after one rework: (1) multi-word ARIA names normalized correctly; (2) property and attribute spellings reconciled; (3) whole-attribute writes conflict with partial ones. Reviewer edit: the LTC084 message names each writer by its own target. Accepted as is: the parent's write channel is the reference-targeted `watch` binding (compose content admits nothing else today; LT-515 would widen it); the deferred custom-tag edge case; properties and attributes treated as one write. Coverage matches LT-474: declared `first()` references only.
