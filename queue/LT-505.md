**Area:** compiler
**Changed:** The `compose` variant of `RenderedShape` carries its site's static attributes and its dynamic `class`/`id`/`data-*` names (`composeSiteAttrs`), the set `emit-server.ts` splices onto the child's root. `leakChildrenFor` merges them into each composed child's host at every level of nesting, so LTC087 sees a class set only at a grandchild's compose site; a dynamic site attribute is a possible match at the top level too. Pinned in `css-leaks.test.ts`.
**Review:** Approved (2026-10-08). Verified: with module-coloreditor's limit removed, LTC087 names `.hue`, `.lightness` and `.chroma`; restored, the baseline is unchanged. No new walk: the site attributes are recorded once per component in the registry pass. Accepted as is: `composeStaticAttrs` also merges static args that never render as attributes (`label="x"`), which can only make LTC087 warn more, the direction it already errs in; `composeSiteAttrs` repeats `emit-server.ts`'s `isComposeHostAttr` predicate rather than importing across the analysis/emit seam.
